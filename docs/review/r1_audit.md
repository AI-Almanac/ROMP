# R1 audit: commit 1ffc0cb (and 4de2fed)

Read-only review of "Clean up: one config error type and one CLI, legacy modes removed, duplicates and dead code
deleted" (three concurrent agents R1a/R1b/R1c) and the follow-up converter fix 4de2fed. Nothing in the code was
changed by this audit.

Baseline: `.venv/bin/python -m pytest -n auto -q` on 37648ff gives **4200 passed, 23 skipped** (132 s). The skips are
the same kinds as before the commit: 1 `onset_forest` not importable, 14 `HCWF_TEST_DATA` real-data checks, 7 "curve
rules never use the PRIOR search", 1 no AIFS_v2 file. 1ffc0cb adds or removes no `skip`/`xfail` markers apart from
`tests/test_parallel.py:105`, which now also skips when the untracked baseline config still has `wet_init:` (see C-8).

## How the checks were made

* **End-to-end legacy parity.** I checked out `1ffc0cb^` in a temporary worktree (since removed) and ran its legacy mode
  on six of the untracked baseline configs in `data/phase7/baseline/` (`eth_det`, `eth_veto`, `eth_ens`, `ind_det`,
  `demo_veto`, `demo_ens`, which still have the flat keys). Region `India` was spelled `india` in both runs so the
  approved box change does not mix in. I then converted each config with the current `hcwf-run convert` and ran it on
  HEAD, and compared every `.nc` data variable and `.csv` table exactly (configs and outputs are in
  `/tmp/claude-1000/-home-hcwf-code-ROMP/f3fbeea6-493c-485b-bfb6-ad02edb09411/scratchpad/r1audit/`).
* **Fingerprint, cache key and error experiments**, old tree against new, are described in each finding.
* **align_sample parity.** `check_labels(..., use_cache=False)` on the Ethiopia and India baseline data gives
  reports with byte-identical `repr` in the old and new trees (both labels).

## Checked and found correct

* **Legacy removal is complete in code.** None of the removed names (`is_legacy`, `detect_legacy`, `check_conflicts`,
  `_legacy_setup`, `from_flat_config`, `LegacyConfigError`, `onset_legacy`, `legacy_boxes`/`legacy_domains`,
  `load_thresh_file`, `_check_steps`, `read_legacy`, `convert_file`, `handled_without_run`, `FLAT_KEYS`,
  `LEGACY_BOUNDARY`) is referenced from `hcwf/`, `scripts/`, `tests/` or notebooks. Docs under `docs/review` and
  `docs/blend_merge` still mention them, which is fine because those are historical. The functions that lost the flat
  parameters (`compute_metrics_multiple_years`, `multi_year_forecast_obs_pairs`, `create_score_results`,
  `compute_climatological_onset_dataset`, `compute_climatology_as_forecast`, ...) take `**kwargs`. Stale keys in a flat
  dict are swallowed there, so R-4 is the place to stop them.
* **The converted rule matches the old one.** I compared `flat_onset_to_rule` with `git show 1ffc0cb^:hcwf/onset/legacy.py`.
  The wet day, `WetDays(1..w, ge w)`, `Total(1..w) gt amount`, the veto condition (`dry_extent > wet_spell and >= dry_spell`, days 2..dry_extent+1),
  the season start (`earliest_onset_date` / `mok` / start_date / 1 Jan) and end (end_date + 47 − (w−1)), the

  the climatology DOY files are IDENTICAL in all six configs. The only differences are B-1, B-2, R-5 and R-7.

  is equivalent to the old two-step logic. `find_pattern`/`_years_in` use the whole-number rule (the old `YEAR_RE`;
  `match.start/end` are the same because the lookarounds are zero-width). `_listed_years`, `config_yaml:59`,
  `check.py:221`, `blend/features.py:77`, `io/input.py:540` and `resolve_paths` use the loose (onset_blending) rule, as before.
* **align_sample on Store.** The cache parts cover everything the old fingerprint did: lead label, both boundaries, the
  16 keys plus `obs_paths`/`obs_files_years`/`model_paths`/`model_files_years`, both pattern lists, the file

## Tests removed or changed (3.)

All of the following are justified by approved removals: the legacy tests in `test_onset_hcwf_legacy.py`,
`test_earliest_onset_date.py`, `test_onset_hcwf_config.py` (4), `_dry_check` (1), `_history` (1),
`_explain_cells` (1), `_lead_window` (1) and `_loader` (1); `test_onset_hcwf_adapter.py::test_too_few_forecast_steps...`
and its legacy alignment-skip half; the config.in byte-for-byte tests in `test_run_config_yaml.py`; the
`legacy_domains` tests; `test_generate_config` flat defaults; the `earliest_onset_date` parametrisation in
`test_stats_vectorised`; the `engine.regional` tests (function deleted; `test_spatial_units` now checks the
one-row transform against an independent weighted mean at rtol 1e-9); `with_ids`/`to_frame` (functions deleted).

Coverage lost or weakened that is not covered by an approval:

* Tests that ran in legacy mode were moved to `old_flat_rule.old_rule`. Their expected values stayed the same, but the helper
  omits `forecast_history="none"`, so they no longer test what legacy runs produced (B-1). Tests that depended on
  "no back-dated column" now pass `forecast_history="none"` explicitly.
* No test runs a converted config end to end against the old outputs. That is how B-1 got through.
* `test_parallel.py:105` will skip silently whenever the untracked baseline config is in the old format (C-8).
